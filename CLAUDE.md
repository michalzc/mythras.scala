## Project Overview

A Scala.js implementation of the Mythras tabletop RPG system for FoundryVTT. The build compiles Scala to JavaScript (ES modules), then bundles it with LESS stylesheets, Handlebars templates, YAML configs, and plain JS into a deployable FoundryVTT system package.

## Build System

Uses [Mill](https://mill-build.org/) (version specified in `build.mill` header: `//| mill-version: 1.1.2`). Run via the `./mill` wrapper or `mill` if installed globally.

### Common Commands

```bash
# Development build (fastLinkJS — faster, unoptimized)
./mill foundry-package.buildDev

# Production build (fullLinkJS — optimized/minified)
./mill foundry-package.buildProd

# Run tests (ScalaTest, runs in JS via Scala.js)
./mill mythras-shared.test

# Run a single test class
./mill mythras-shared.test.testOnly michalz.foundry.mythras.services.AttributesServiceSpec

# Compile only (no linking)
./mill mythras.compile

# Format code (Scalafmt)
./mill __.reformat

# Run Scalafix linter/rewrites
./mill __.fix

# Show current version
./mill version-file.currentVersion
```

Build output lands in `out/` (Mill's cache/artifact directory). The `foundry-package.buildDev` task assembles everything into `out/foundry-package/buildDev.dest/`, which is the deployable FoundryVTT system directory.

## Module Architecture

The project has four Mill modules with a clear separation of concerns:

### `scala-types`
Scala.js type bindings for the FoundryVTT client API (actors, items, sheets, hooks, etc.). These are `@js.native` facades that map to FoundryVTT's global JavaScript runtime objects (`Hooks`, `Game`, `Actors`, `CONFIG`, etc.). No application logic here — purely type-safe wrappers over the FoundryVTT API.

### `mythras-shared`
Pure Scala business logic (no Scala.js DOM or FoundryVTT dependencies). Contains Mythras RPG rule calculations: `AttributesService`, `DamageModifierService`, body location hit point tables, etc. This is the only module with tests (ScalaTest + ScalaCheck table-driven tests via `mythras-shared.test`).

### `mythras` (depends on `scala-types` + `mythras-shared`)
The main Scala.js application module. Compiled as an ES module (`ModuleKind.ESModule`). Key subsystems:
- **`init/`** — FoundryVTT `Hooks.once("init", ...)` registration; wires up all document classes and sheets
- **`document/actor/`** — `MythrasActor` extends the FoundryVTT `Actor` document; `data/` contains `js.Object` data model traits; `state/` contains lazy-computed derived state (characteristics, attributes, items)
- **`document/state/StateHolder`** — invalidation cache pattern: stores computed state, wiped on `prepareData()` calls
- **`application/`** — `MythrasBaseSheet`, `MythrasCharacterSheet`, `MythrasNPCSheet` extend FoundryVTT's `ActorSheet`; pass `ActorState` into Handlebars context via `getData()`

### `foundry-package`
The packaging module. Not a Scala module — orchestrates the full build:
- Runs `mythras.fastLinkJS()` or `mythras.fullLinkJS()`
- Converts YAML → JSON (YAML files in `src/main/yaml/`, except `system.yaml` which becomes `system.json` with version injected)
- Compiles LESS → CSS via less4j (entry: `src/main/less/mythras.less`)
- Copies static resources (`src/main/resources/`) and plain JS files (`src/main/js/`)

## Scala/JS Interop Patterns

- **FoundryVTT native objects** → `@js.native @JSGlobal` facades in `scala-types`
- **Scala → JS export** → `@JSExportTopLevel` on classes (e.g., `MythrasActor`), `@JSExportStatic` on companion object methods (required for FoundryVTT's `name` and `defaultOptions` static properties)
- **Data models** are defined in plain JS (`foundry-package/src/main/js/datamodel/`), not Scala, because FoundryVTT's `DataModel` schema DSL (`foundry.data.fields.*`) cannot be easily represented in Scala.js
- **`MythrasAddons`** (`addons.js`) bridges the JS data model registration into the Scala entry point via `registerDataModels()`

## FoundryVTT System Entry Point

The FoundryVTT manifest (`system.yaml` → `system.json`) declares `modules/main.js` as the ES module entry point. `main.js` is generated by Scala.js's linker from `mythras/src/main/scala/michalz/foundry/mythras/init/init.scala`, which calls `HooksRegister.registerAll()` to hook into `Hooks.once("init", ...)`.

## Version Management

Version is tracked in `version-file/version` (currently `0.1.0-SNAPSHOT`). The `foundry-package` build reads this via `version-file.currentVersion()` and injects it into `system.json`.

## Scala Configuration

- Scala 3.8.2, Scala.js 1.20.2
- Compiler flags: `-explain`, `-Wunused:all`, `-deprecation`, `-feature`
- Cats Core for functional utilities in `mythras-shared`
- ScalaTest for tests in `mythras-shared`
